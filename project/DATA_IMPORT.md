# 50场真实会议数据录入

范围：2018—2026年，采集截止2026年10月26日。其中2026年10场，其余40场为往年会议。

## 执行顺序

已有数据库时，先备份，再运行新版02_create_tables.sql、03_insert_data.sql、04_views.sql、06_routines.sql。02会删除并重建12张表。首次建库先运行01_create_database.sql。

03是空表初始化脚本，执行一次即可；它不删除已有数据，不关闭外键检查，也不使用INSERT IGNORE隐藏冲突。需要重建时重新运行02、03。完整的一键入口仍按01→02→03→04→06→05→07→08→99执行。

## 课件对应

- 《14-15 3.4-3.5 SQL的数据更新和视图》第6页：INSERT INTO 表名（列名表）VALUES（元组值）。
- 同课件第7页：同表多元组插入，一条INSERT写多组VALUES，减少重复语句。
- 同课件第6页的空成绩示例：整列未知且默认NULL的字段省略；部分已知的列逐行写NULL。例如人数整列未知时不重复填写304组NULL。
- 《10 3.1-3.2 SQL简介和数据定义》第28—29页：NOT NULL、PRIMARY KEY、FOREIGN KEY和CHECK。未知值允许NULL，已知值仍检查范围。
- 先录入国家、国际组织，再录入机制、去重议题、会议及其参会/议题关联、文件、联署和行动。显式指定本次初始主键，使外键对应清楚。事务用于整批提交；发生错误时停止执行并ROLLBACK。

## 字段与来源

完整采集资料保存在[data/真实数据.json](data/真实数据.json)，包括125个官方来源、网页日期、原文位置和采集日期。国家英文名、ISO三位代码及地区归属按[联合国统计司M49](https://unstats.un.org/unsd/methodology/m49/overview/)核对，美洲在本项目按南美洲、北美洲（含中美洲及加勒比）归类。联合国会员标记依据[会员国名单](https://www.un.org/en/about-us/member-states)与[非会员观察员国名单](https://www.un.org/en/about-us/non-member-states)，巴勒斯坦为0。发展类别本次未统一核验，写NULL。

- C01对应conference_id=1，D01对应document_id=1，A01对应action_id=1；以此类推。国家和议题按本次SQL中的字典主键关联。机制类别为项目分类，SCO-HS、SCO-HG、SCO-FM为项目区分简称。
- 会议采用实际结束日期，原定日期保留在采集JSON。host_country_id表示举办地国家；线上会议为NULL。C40由中国政府在纽约主办，举办地国家为美国，org_id为NULL，不把中国政府当成国际组织。
- doc_type保留官方文件性质，如宣言、决定、主席声明、条约、议定书；不将签署推定为生效。issue_date的具体日期依据、通过日和发布日均可在JSON逐项核对。
- 代表团人数、确认日期、未知代表级别、未知会议形式、核心议题标记、未知通过方式均写NULL。实际代表姓名、职务及已核实活动日保存在JSON；join_date表示确认参会日期，不拿活动日替代。
- 38项行动都是公开目标或承诺。目标数、单位和原文时间范围写入remarks；牵头国家不明时写NULL。未查到精确启动日、完成日、状态和进度，不填虚构日期或0%。
- 45条联署只录入已明确签署的国家，不按参会名单批量推定。

## 与原表结构的必要调整

保留12表及全部主外键。02仅放宽真实未知字段的非空限制，补充文件类别、专题会议、对话伙伴及文件已发布/已签署状态。CHECK继续约束已知数据。

04与06中的可空国家关联使用LEFT JOIN，避免线上会议及集体行动在查询中消失。06审计触发器补充NULL变化比较，原有CRUD示例仍在事务末尾回滚。

原backup目录为旧版示例快照，未包含本次50场资料；本版以01—03重建为准。

## 本次验证

2026年10月26日在独立临时MySQL 8.4.11中执行，启用严格模式与ONLY_FULL_GROUP_BY。10张业务表的5036个字段值逐一与生成清单核对一致，原始采集JSON完整保留。50场会议的视图结果齐全，线上会议及牵头国家未明确的行动可正常查询。

05核心查询、07事务回滚示例、08课件示例、99自检均执行成功；检查了非法外键、日期、人数、进度、分类值及文件/会议不一致的拒绝行为。审计可记录NULL与已知值之间的双向变化。03重复执行会明确报主键冲突，未删除或重复现有记录；重新执行新版02、03可正常重建。

验证过程仅使用独立临时数据库，未修改现有业务数据库；旧版备份尚未重新导出。
