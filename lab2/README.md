## 三、查询设计要点

- **在借册数**（1.(1)⑤）用列间运算 `total_copies - available`，不是另存字段——统计值由基数据实时算出，避免冗余。
- **分类图书名称**（1.(2)①）用 `GROUP_CONCAT(title ORDER BY book_id SEPARATOR '、')` 把同一分类的书名串起来，配合 `SUM(total_copies)` 出馆藏合计。
- **多层连接**（1.(2)③④⑥）走「借阅记录 → 读者 / 图书 → 分类 / 出版社」四表链，正是实验一建的外键在支撑。
- **`HAVING` 过滤分组**（1.(2)⑤、1.(3)⑥）：先 `GROUP BY` 出版社再按数量筛，`> 子查询` 与上海译文出版社对比。
- **`ALL` 子查询**（1.(3)④）：`price > ALL (SELECT ... WHERE 分类='经济管理')`，语义是「比经济管理里最贵的那本还贵」，用 `ALL` 而不是 `MAX()` 更贴题意。
- **`IN` / 相关子查询**（1.(3)②③⑤）：同类型对比、有在借记录、借过某类书，三种典型写法。
- **`DISTINCT` 去重**（1.(1)①、1.(2)⑥）：出版社城市、读者-图书组合。

## 五、完整性约束（第 3 部分）

实验一的建表语句里已经带了同类约束（`uk_readers_card_no`、`ck_readers_gender`、`ck_books_available`），
为了让「添加约束」这一步看得见且脚本可重复执行，`05_constraints.sql` 统一采用
**先查 `information_schema` → 有就删 → 再加** 的动态 SQL 写法（`PREPARE/EXECUTE`）。

| 题 | 操作 | 验证方式 | 实测报错 |
|---|---|---|---|
| 3.① | `card_no` 加唯一约束 | 插入重复证号 `RD20230001` | `ERROR 1062 Duplicate entry` |
| 3.② | `gender` 加 `CHECK IN ('男','女')` | 插入性别 `F` | `ERROR 3819 ck_readers_gender` |
| 3.③ | `available` 加 `CHECK (> 0 AND <= total_copies)` | 把可借册数改成 999 | `ERROR 3819 ck_books_available_positive` |
| 3.④ | 约束改为 `>= 0 AND <= total_copies` | 把可借册数改成 −1 | `ERROR 3819 ck_books_available` |

4 条非法写入全部被拒，`readers` / `books` 收尾仍是 10 / 10 行——约束在库内真实生效，脏数据一条没进。

- `04_updates.sql` 会永久改数据，单独跑两遍会重复加册数；要么先重跑实验一 01~04，要么直接用 `run_all.cmd`（它已经帮你复位）。
- `05_constraints.sql` **必须带 `-f`**：不加就会在第一条故意制造的报错处中断，后面 3 题不会执行。
- 库名写死 `library_db071`；学号后 3 位不是 071 就全局替换。
- 指导书文件名里的「改错版」指这是修订版指导书，正文没有需要改错的代码，按题实现即可。
